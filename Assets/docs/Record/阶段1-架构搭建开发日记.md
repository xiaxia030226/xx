

先熟悉 QFramework 的架构，，让场景里有个能动的角色，再加一条能实时刷新的血条



整个游戏的入口是 `GameRoot`，挂在场景里，Awake 里按顺序做三件事：初始化输入、初始化架构、搭场景，代码生成灯光、地面、围墙、相机

```csharp
// GameRoot.Awake 的主线
GameInput.Init();
GameArchitecture.Init();
CreateEnvironment();
CreatePlayer();
CreateCamera();
UIKit.OpenPanel<GameHUD>();
```

## 输入：Input System

新项目直接用新输入系统（Input System），但没走可视化编辑器那套 `.inputactions` 资产，而是在 `GameInput` 里纯代码 new 出 `InputAction`：WASD 合成 Vector2、鼠标位置、外加几个调试键（K 扣血、H 回血、L 回满）。

这么做的好处是**输入定义跟着代码走，版本管理友好**，改键位不用开编辑器点来点去。取值方式统一成 `GameInput.Move.ReadValue<Vector2>()`，到处用都很顺手。

## 架构核心：GameArchitecture + Model

`GameArchitecture` 是 QFramework 的容器，目前就干一件事——注册两个 Model：

- `PlayerModel`：血量、移速这些玩家数据
- `GameStateModel`：游戏状态（预留）

关键在 `BindableProperty<T>` 这个类型：**值一变就自动发事件**。所有数据字段都声明成它，后面的 UI 自动刷新全靠这一条。

## 角色：Player 和 CameraFollow

`Player` 是目前唯一的玩法逻辑。Update 里读输入、从 Model 读移速、移动、钳制边界；转向是拿主相机往鼠标位置打射线，和地面求交点。注意它从头到尾**只读 Model，从不写**——想改数据？发 Command。

`CameraFollow` 就十几行，一个带平滑的跟随，独立无依赖。

## Command：改数据的唯一入口

`PlayerTakeDamageCommand` 和 `PlayerHealCommand` 是目前仅有的两个命令，结构固定：构造函数传参，`Execute` 里拿到 Model 改值。调试键的链路是：

```
按 K（GameInput）
  → GameRoot 发 PlayerTakeDamageCommand
    → Command 改 PlayerModel.HP.Value
      → BindableProperty 触发事件
        → GameHUD 收到回调刷新血条
```

这条链路就是整个架构的缩影，以后加任何"数据驱动表现"的功能都是这个套路。

## UI：GameHUD 和 UIKit 代码生成

HUD 用 QFramework 的 UIKit 做。`GameHUD` 在 `OnInit` 里用 `RegisterWithInitValue` 订阅 HP 和 MaxHP，数据一变就刷血条——血条没有用 Image.fillAmount，而是用 anchor 拉宽度实现的，后面做样式更灵活。

这一阶段的另一个收获是摸清了 UIKit 的**代码生成工作流**，之前一直半懂：

1. prefab 建在 `Assets/Resources/UI/` 下，名字 = 类名
2. 需要代码访问的控件改好名、挂 **Bind** 组件
3. Project 窗口选中 prefab，**右键 → @UI Kit - Create UICode（或 Alt+C）**
4. 生成器自动产出 `XxxPanel.cs` + `XxxPanel.Designer.cs`，编译后自动挂脚本、自动赋值

两个容易踩的坑记一下：

- **Designer 文件不要手写也不要手改**，每次生成都重写；`.cs` 骨架只在文件不存在时生成，之后随便写逻辑不会被覆盖
- Inspector 上的"生成代码"按钮只在已挂 UIPanel 脚本时才出现，**新面板首次生成必须走右键菜单/Alt+C**，这个坑我踩过

`GameUIKitConfig` 负责把 `OpenPanel<GameHUD>()` 翻译成 Resources 下的 prefab 路径，属于管道设施，不理解也不影响写业务。
